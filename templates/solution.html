详细说明

把域名指向展示页，需要做的只有三件事

这套模板不会改变你的域名解析结构，也不需要你部署任何东西。你需要的只有两样：一个已经完成备案的域名，以及域名商提供的 URL 转发功能。

去首页生成链接 先看注意事项

开始前需要确认两件事

这两件事不满足，后面的操作不会生效。

一、域名已完成备案

URL 转发是域名商提供的一项服务，通常要求该域名已经完成 ICP 备案。具体限制以你所用服务商的说明为准。

二、域名商提供 URL 转发

它不是把域名解析到某个 IP，而是由服务商在访问时返回一次跳转。请在控制台里确认存在「URL 转发」这一类功能。

三步操作

选模板、生成链接、填进转发记录。

第 1 步：选一个模板

  • 在首页挑选风格，点开卡片即可在浏览器里预览实际效果。
  • 模板样式是固定的，你不需要改动任何代码。

第 2 步：生成完整链接

  • 在首页的生成器里填入你的备案号。
  • 可选填品牌名、一句话说明和你的站点链接，它们会显示在模板页上。
  • 复制生成的完整链接，链接里的参数已经做过百分号编码，可直接粘贴。

第 3 步：新增转发记录

  • 在域名商的 URL 转发功能里新增一条记录。
  • 把上一步复制的完整链接填进记录值，保存后等待生效。
  • 用你自己的域名访问一次，确认页面和页脚的备案号都正确。

验证清单

  • 页面是否正常打开、样式是否完整。
  • 页脚显示的备案号是否与你的备案信息一致。
  • 移动端打开是否同样可用。

各平台的叫法差异

同一个功能在不同服务商那里名字不一样，下面的叫法仅供参考，具体入口与选项请以官方文档为准。

阿里云云解析

在解析记录里提供 URL 转发相关的选项。入口位置和命名可能随版本变化，请以阿里云云解析的官方文档为准。

腾讯云 / DNSPod

记录类型里通常区分「显性 URL」和「隐性 URL」。两者的区别是访问时地址栏显示的是目标地址还是你自己的域名。

Cloudflare 等 DNS 服务

一般通过 Rules 里的重定向规则实现，配置方式与国内域名商的控制台差别较大，请以官方文档为准。

关于显性与隐性：隐性转发会在地址栏保持你自己的域名；显性转发会把地址栏里的地址替换成目标地址，访问者会看到展示页的实际路径。如果你不希望访问者看到目标地址，需要先确认你的服务商提供隐性转发。

需要注意的几点

URL 转发属于域名商提供的服务，是否支持、是否收费、是否要求备案均由服务商决定，本页不对任何服务商的具体功能作出保证。

部分服务商不支持带查询参数的转发，或对记录值的长度有限制。如果遇到这种情况，可以只保留备案号这一个参数。

展示页托管在公开的 GitHub Pages 上，中国大陆的访问稳定性可能受网络环境影响。

多个域名转发到同一个展示页会产生重复内容，对搜索引擎收录不一定有利。

以上只是常见情况，实际配置请以你所用服务商的官方文档和当地监管要求为准。
